# Security policy

## Reporting a vulnerability

Please **do not open a public GitHub issue** for a suspected vulnerability that could enable unauthorized code execution, bypass verified boot, expose keys or personal data, compromise updates, or brick devices.

Use GitHub's private security-advisory reporting for this repository if it is enabled. If it is unavailable, contact the repository owner privately through the contact method listed on the GitHub profile and include:

- affected component and version/commit;
- a concise impact statement;
- safe reproduction steps or proof of concept;
- whether details have been shared elsewhere; and
- a secure contact method for follow-up.

Do not include private keys, user data, or destructive instructions in an initial report.

## Response objectives

The project aims to acknowledge reports within 7 days, triage severity and scope promptly, coordinate a fix and release plan before public disclosure where possible, and credit reporters who want credit. These are goals, not yet a service-level agreement for an unreleased research project.

## Supported versions

There are no released UniversalOS versions yet. Security work currently applies to the planning branch and any future explicitly supported preview release.
